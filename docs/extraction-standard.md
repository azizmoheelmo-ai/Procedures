# معيار استخراج الأدلة (Extraction Standard)

هذا المعيار يحكم كيف يدخل أي دليل جديد إلى المجمّع، بدءاً من الملف الرسمي
وانتهاءً بسجلّ في قاعدة البيانات له استشهاد دقيق بالصفحة والبند. الهدف: بيانات
موثوقة يمكن الاعتماد عليها، لا استخراج سريع قد يحمل أخطاء صامتة.

## 1. شروط قبول الملف

قبل البدء بأي استخراج، يجب أن يتحقق الملف المصدر مما يلي:

- **نسخة رسمية**، صادرة عن وزارة التعليم أو الجهة المختصة، وليست مسودة أو ملخصاً.
- **طبقة نص قابلة للتحديد** (selectable text layer)، لا صفحات ممسوحة ضوئياً
  فقط كصور. إذا كان الملف صوراً بلا طبقة نص، يُمرّر أولاً عبر التعرف الضوئي
  على الحروف (OCR)، ثم يُعامل الناتج كأي نص آخر ويخضع لنفس الفحوصات أدناه.
- **إصدار وتاريخ معروفان**: أي نص على الغلاف أو الصفحة الأولى يحدد رقم/تاريخ
  الإصدار (مثل «1446-1447هـ»)، يُستخرج ويُسجَّل في `version.version_label`
  و`version.issue_date`.
- **عدد الصفحات معروف**، ويُسجَّل في `version.total_pages`. يُستخدم لفحص
  تغطية الصفحات (§3).

ملف لا يحقق هذه الشروط لا يُستورد؛ يُذكر السبب في تقرير طلب الدمج بدلاً من ذلك.

## 2. القالب العام للاستخراج

معظم أدلة الوزارة تتبع بنية متكررة:

```
الدليل → الأبواب/الأقسام → المواد/البنود → الفقرات
```

القالب العام (`data/<code>.json`) يعكس هذه البنية كشجرة `sections` متداخلة،
كل عقدة فيها قسم من الدليل وقد تحوي عناصر محتوى (`blocks`) و/أو أقساماً فرعية
(`children`):

```jsonc
{
  "guide": {
    "code": "behavior_regs",              // snake_case، فريد
    "name_ar": "لائحة السلوك والمواظبة",
    "short_name": "لائحة السلوك",         // يظهر في الاستشهاد
    "guide_type": "regulation",           // procedures|regulation|job_description|org_structure|other
    "description": "..."                  // اختياري
  },
  "version": {
    "version_label": "1446-1447هـ",
    "issue_date": "2025-01-01",           // أو null إن لم يُعرف اليوم والشهر
    "source_file": "behavior-regs.pdf",
    "total_pages": 40
  },
  "table_of_contents": [                  // اختياري، يُستخدم في فحص §3.3
    { "title": "الباب الأول: أحكام عامة", "page": 3 }
  ],
  "sections": [
    {
      "code": "الباب الأول",              // رقم/عنوان القسم كما طُبع، أو null
      "title": "أحكام عامة",
      "page_start": 3,
      "page_end": 5,
      "blocks": [
        { "block_type": "article", "seq": 1, "page": 3,
          "text": "المادة (1): ..." }
      ],
      "children": [
        {
          "code": "الفصل الأول",
          "title": "التعريفات",
          "page_start": 3,
          "page_end": 4,
          "blocks": [ { "block_type": "article", "seq": 1, "page": 3, "text": "..." } ]
        }
      ]
    }
  ]
}
```

- **`code`** يحمل رقم/اسم القسم كما هو مطبوع في الدليل (باب، فصل، مادة، بند).
  هذا ما يبني منه `get_citation()` نص الاستشهاد، لذا يجب أن يطابق المطبوع
  حرفياً، لا ترقيماً مُعاداً توليده.
- **عمق الشجرة غير محدود**: قسم قد يحوي أقساماً فرعية إلى أي مستوى (باب ←
  فصل ← مادة)، والمحوّل العام (`scripts/guides/generic.mjs`) يبني منها
  `level` و`parent_id` تلقائياً.
- **`block_type`** يُختار من: `step, raci, policy, input, output, form, kpi,
  article, task, system, note`. الأدلة التنظيمية والأنظمة تستخدم غالباً
  `article` (نص مادة/بند) و`task` (مهمة) و`note` مع `metadata.kind` لأي شيء
  آخر (تعريف، حاشية، ملاحظة).
- **لا اختراع ولا إعادة صياغة**: النص المنقول في `text` يجب أن يكون نص الدليل
  نفسه، دون تلخيص أو تصحيح أسلوبي. أي تصحيح لخطأ استخراج (حرف مقلوب مثلاً)
  يُوثَّق في تقرير الجودة، لا يُصحَّح بصمت.

أدلة ببنية مختلفة جوهرياً (كدليل الإجراءات ذي مجموعات/إجراءات متعددة الأبعاد)
تحتفظ بمحوّل خاص بها (`scripts/guides/procedures.mjs`، `org-manual.mjs`)؛
القالب العام لا يجبرها على التوافق، لكنه الخيار الافتراضي لأي دليل جديد.

## 3. الفحوصات الآلية الإلزامية

تُشغَّل عبر `npm run validate-guide -- <code>` (أو `--pdf <path>` لتفعيل فحص
نسبة الاستخراج). تطبع تقريراً بالعربي، وتخرج برمز غير صفري عند فشل فحص حاسم.

### 3.1 تغطية الصفحات
لكل صفحة بين 1 و`total_pages`، هل يوجد فيها قسم أو عنصر واحد على الأقل؟
الصفحات الفارغة من الاستخراج (باستثناء صفحات الغلاف/الفهرس المعروفة) تُبلَّغ.

### 3.2 تسلسل الترقيم
لكل مجموعة أقسام تحت نفس الأب، تُستخرج الأرقام من `code` (حين تكون رقمية أو
شبه رقمية) ويُفحص التسلسل: فجوة (قفز من 5 إلى 7) أو تكرار (نفس الرقم مرتين).
الأكواد غير الرقمية (مثل «الباب الأول») تُستثنى من هذا الفحص تحديداً.

### 3.3 مطابقة الفهرس
إن وُجد `table_of_contents` في الملف المصدر، يُتحقق أن كل عنوان فيه موجود
حرفياً أو بتقارب كبير بين عناوين الأقسام المستخرجة.

### 3.4 تشوّه النص العربي
- **حاسم**: وجود محارف Arabic Presentation Forms (النطاق Unicode
  U+FB50–U+FDFF أو U+FE70–U+FEFF) في أي نص — علامة أكيدة على استخراج معطوب
  لم يُعِد تشكيل الحروف بشكل صحيح.
- **حاسم**: ألفاظ معروفة الفساد من كثرة تكررها في استخراجات سابقة (مثل
  «إلدارة» بدل «لإدارة»، «إلعداد» بدل «لإعداد»).
- **تنبيه**: سطر عربي يحوي حروفاً لاتينية متتالية لا تبدو اختصاراً معروفاً.

### 3.5 نسبة الاستخراج إلى المصدر
إذا مُرِّر ملف PDF (`--pdf`)، يُقارَن مجموع طول النصوص المستخرجة بطول نص PDF
الخام. نسبة أقل من 50% أو أعلى من 150% تُبلَّغ كتنبيه، لأنها قد تعني فقدان
محتوى أو تكراره.

### 3.6 عناصر فارغة أو مكررة
نص فارغ بعد إزالة المسافات (لا يجب أن يصل أصلاً لأن `block()` يتجاهله)، أو
عنصرا محتوى بنفس النوع والنص حرفياً في مكانين مختلفين من الدليل (كما حدث سابقاً
مع بطاقتَي «المعلم» في الدليل التنظيمي، قبل دمجهما).

## 4. تقرير الجودة

كل استيراد جديد يُرفق تقريره في نص طلب الدمج، ويتضمن:
- نتيجة كل فحص من §3 (✓/✗ مع العدد).
- قائمة مختصرة بالمواضع التي يُستحسن أن يراجعها صاحب المشروع بعينه (صفحات
  مفقودة، فجوات ترقيم، تشوّهات نصية لم تُصحَّح آلياً).

الاستيراد **لا يُفتح له طلب دمج** إن فشل في أي فحص حاسم (§3.4) قبل أن يُعاد
الاستخراج وتُصحَّح المشكلة.
